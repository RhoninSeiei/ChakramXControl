# HID 协议与实现说明

本文记录 Chakram X Control 当前使用的 P708 配置报文。字节布局依据公开实现、原厂组件静态分析和本项目开发期间的有线实机验证整理。协议未覆盖的字段保持原始值，扩展功能时需要重新核对目标型号和固件行为。

## 设备识别与验证范围

配置接口通过 hidapi 枚举，筛选条件与 `device.py` 保持一致。

| 字段 | 条件 |
| --- | --- |
| VID | `0x0B05` |
| 有线 PID | `0x1A18` |
| 原配 2.4 GHz 接收器 PID | `0x1A1A` |
| `interface_number` | `0` |
| `usage_page` | 大于等于 `0xFF00` |
| `usage` | `1` |

本次实机验证使用有线 `0B05:1A18`。`0B05:1A1A` 有代码支持，其型号识别和协议参考来自上游，2.4 GHz 链路仍需独立实测。蓝牙连接、其他型号及跨固件版本的兼容性尚未建立验证覆盖。[设备实现](../device.py)、[G-Helper ChakramX](https://github.com/seerge/g-helper/blob/a3c3ccae51f005d92d8d4ee161e6661ab511274d/app/Peripherals/Mouse/Models/ChakramX.cs)

## 报文封装

下文所有偏移均从协议 payload 的第一个命令字节开始，采用从零计数的字节偏移。多字节整数使用小端序。示例省略尾部填充的 `00`。

Windows hidapi 的写入参数由一个 `00` report-ID 占位字节和 64 字节 payload 组成，总长 65 字节。`Transport._send()` 接收长度为 2 至 64 字节的命令，在右侧补零至 64 字节，然后添加 report-ID 占位字节。当前读接口返回 64 字节 payload，业务模块使用的响应已经不含该占位字节。[传输实现](../device.py)

```text
hidapi 写入    00 | payload[0..63]
hidapi 读取         payload[0..63]
业务命令示例        12 00
```

每次发送前，传输层最多排空 32 个已有输入报告。普通请求等待应答的期限为 1.25 秒，只接收长度为 64 字节且命令前缀匹配的报告。以 `FF AA` 开头的报告作为固件拒绝请求处理。

| 请求类型 | 应答匹配规则 |
| --- | --- |
| 普通 `12` 查询 | 匹配前 3 字节，短请求的第三字节按 `00` 处理 |
| 灯效 `12 03` 查询 | 匹配前 2 字节，采用实机确认的 selector 特例 |
| 普通设置与保存 | 匹配前 2 字节 |
| 游戏控制器接口开关 | 发送后重新枚举和查询状态 |

应用使用 Windows 命名对象 `Local\ChakramXConfigurationSession` 拒绝本应用实例之间的并发配置操作。该机制的覆盖范围是使用同一会话名称的应用实例。其他配置软件和实体按键仍可能改变鼠标状态，因此业务操作还会检查活动预设和有关字段的回读。[会话与应答匹配实现](../device.py)

## 当前状态、预设与保存

查询活动状态使用 `12 00`。

| 响应偏移 | 长度 | 含义 |
| --- | --- | --- |
| `0` | `2` | `12 00` |
| `10` | `1` | 活动板载预设，原始值 `0..4` |
| `11` | `1` | 活动 DPI 档位，原始值 `1..4` |

公共 API 和界面使用预设 `1..5`，因此对偏移 `10` 的值加一。DPI 档位沿用响应中的 `1..4`。预设号与 DPI 档号分别解释，即使两个档位具有相同 DPI 数值，也根据实际档号识别当前生效项。

```text
响应节选    12 00 00 00 17 02 22 00 05 07 01 03 FF FF
解析结果    板载预设 2，DPI 档位 3
```

切换板载预设使用 `50 02 p`，其中 `p` 为 `0..4`。当前实现随后发送 `50 03` 保存，再通过 `12 00` 核对活动预设。普通配置命令操作当前活动预设，报文中的保留字节保持为零。

`50 03` 将当前配置提交到板载存储。单字段写入的应答表示该命令得到响应，业务层继续读取有关配置以确认结果。`persist=False` 用于延迟发送保存命令，调用方负责后续保存及验证。[状态与 DPI 实现](../performance.py)、[预设切换实现](../buttons.py)

## DPI 数值与档位

读取四档 X、Y 数值使用 `12 04 02`。读取四档指示颜色使用 `12 04 03`。令 `i` 为从零计数的档位索引。

| 响应 | 偏移 | 内容 |
| --- | --- | --- |
| `12 04 02` | `4 + 4*i` | X 数值的编码，2 字节小端整数 |
| `12 04 02` | `6 + 4*i` | Y 数值的编码，2 字节小端整数 |
| `12 04 03` | `4 + 3*i` | 该档的 R、G、B，连续 3 字节 |

```text
DPI = encoded * 50 + 50
encoded = DPI / 50 - 1
```

当前数值设置接口支持 `100..36000`，步进为 `50`，将选中档位的两轴设为同一数值，并保留该档原有指示颜色。读取时分别保留 X、Y 的实际值。

```text
51 31 i 00 dpi_lo dpi_hi R G B
```

例如，将第二档设为 1250 DPI，并保留指示颜色 `(12, 34, 56)`，payload 为 `51 31 01 00 18 00 0C 22 38`。保存后的验证同时检查 X、Y 数值和指示颜色。

切换当前 DPI 档位使用 `51 31 09 00 s`，其中 `s` 为 `1..4`。保存后通过 `12 00` 的偏移 `11` 确认当前档位。四档读取、独立两轴解析、颜色保留和边界编码具有自动测试覆盖，其中测试保留了一组有线实机捕获。[DPI 实现](../performance.py)、[DPI 回归测试](../tests/test_performance.py)

## 鼠标按键与四个侧键

查询按键映射使用 `12 05 g 00 00`，其中 `g` 为分组 `0` 或 `1`。响应的偏移 `2` 对应该分组。每个原始位置占 2 字节，动作为小端整数，偏移计算为 `4 + 2*position`。

| 界面或内部槽位 | 物理源动作码 | 分组 | 原始位置 |
| --- | --- | --- | --- |
| 左键，槽位 `0` | `01F0` | `0` | `0` |
| 右键，槽位 `1` | `01F1` | `0` | `1` |
| 滚轮按下，槽位 `2` | `01F2` | `0` | `2` |
| DPI 按钮，槽位 `3` | `01E6` | `0` | `5` |
| 滚轮向上，槽位 `4` | `01E8` | `0` | `6` |
| 滚轮向下，槽位 `5` | `01E9` | `0` | `7` |
| 侧键 A，槽位 `10` | `01EA` | `1` | `2` |
| 侧键 B，槽位 `11` | `01EB` | `1` | `3` |
| 侧键 C，槽位 `12` | `01EC` | `1` | `4` |
| 侧键 D，槽位 `13` | `01ED` | `1` | `5` |

分组中的空洞位置需要保留。分组 `0` 的位置 `3`、`4`，以及分组 `1` 的位置 `0`、`1`，均不对应表中的可读按键。

```text
实机分组 1 节选
12 05 01 00 FF FF FF FF 2E 00 E5 01 E4 01 13 00

A = 002E，键盘 =
B = 01E5，前进
C = 01E4，后退
D = 0013，键盘 P
```

设置单个物理输入使用 `51 21 00 00 src_lo src_hi dst_lo dst_hi`。例如，侧键 C 映射为键盘 A 的 payload 为 `51 21 00 00 EC 01 04 00`。设置后读取该按键校验，保存后再次读取。

动作码的低字节为动作值，高字节参与区分动作类型。菜单中的键盘 A 为 `0004`，四个方向键为 `0052`、`0051`、`0050`、`004F`，鼠标禁用动作为 `01FF`。媒体动作包含本设备使用的扩展编码，解析时应以本项目动作表为准。现有未知动作保留为原始 16 位值并显示十六进制。当前界面提供单键、鼠标功能和媒体动作，组合键与宏需要另外建立实现和验证。[按键实现](../buttons.py)、[按键回归测试](../tests/test_buttons.py)、[上游按键协议](https://github.com/libratbag/libratbag/blob/1aec93b2f81036014063fb8a9ac194a1c71bdec8/src/asus.c)

## 摇杆兼容模式与四方向映射

游戏控制器接口开关对整只鼠标生效，四方向映射属于活动预设。两项配置分别处理。界面允许在预设 `1..4` 编辑摇杆，预设 `5` 的摇杆行为按型号约束处理。[华硕型号说明](https://rog.asus.com/support/faq/1050027/)

### 游戏控制器接口开关

查询使用 `12 00 06`，响应偏移 `4` 为 `0` 或 `1`。设置使用 `51 40 00 00 value`。

| 原始值 | 游戏控制器接口 | 界面“摇杆兼容模式” |
| --- | --- | --- |
| `0` | 隐藏 | 勾选 |
| `1` | 启用 | 取消勾选 |

该设置可能触发 USB 重新枚举。当前传输层发送一次设置命令后关闭配置句柄，再通过重新打开配置接口、查询固件开关及核对 Windows 实际枚举结果确认。等待间隔为 0.2 秒，默认期限为 8 秒。此路径使用开关回读和接口枚举确认完成。

Windows 检查会寻找相同 PID、通用桌面 usage page `1`、usage `4` 或 `5` 的 HID collection，并进一步比较物理设备 Container ID。开发期间，有线实机启用后出现了同一物理设备的 `MI_04` 游戏控制器，其描述符包含 X 和 Y 两个轴。界面的勾选状态来自固件，旁边的检测文字来自 Windows 枚举结果。[开关与枚举实现](../device.py)、[界面开关逻辑](../stick_ui.py)

### 数字方向和模拟轴映射

四方向使用与侧键相同的 `51 21` 设置格式，但物理源码和侧键独立。

| 物理方向 | 物理源动作码 | 默认数字方向键 |
| --- | --- | --- |
| 上 | `01D2` | `0052` |
| 下 | `01D3` | `0051` |
| 左 | `01D1` | `0050` |
| 右 | `01D0` | `004F` |

数字模式可以将四个方向分别映射为支持的动作。模拟模式采用原厂 P708 的方向与轴编码组合。

| 模式 | 上、下的目标码 | 左、右的目标码 |
| --- | --- | --- |
| `analog_vertical` | `01DB` | `01D8` |
| `analog_horizontal` | `01D8` | `01DA` |

原厂转换表中的轴动作分别为 `01D8` 对应 FWD Axis 0，`01D9` 对应 REV Axis 0，`01DA` 对应 FWD Axis 1，`01DB` 对应 REV Axis 1。上表来自原厂预设布局，两个相反方向使用相同轴动作是该布局的原始定义。

当前协议可确认四次方向写入的应答，但缺少可靠的四方向绑定回读。程序在写入前后核对全部可读鼠标按键，并在部分失败时报告已经收到确认的方向。板载保存命令得到应答与实际拨动产生正确键盘输入或轴运动分别需要验证。实际输入可通过程序的按键测试窗口和 Windows 游戏控制器属性检查。

本机布局记录按物理设备 Container ID 和预设保存，用于展示上次成功提交的布局。该记录与设备回读分别标注，其他工具或设备重置会使记录过时。应用模拟布局前会启用游戏控制器接口，应用数字布局时保留原有接口开关状态。[方向映射实现](../buttons.py)、[写入记录实现](../stick_record.py)、[摇杆界面流程](../stick_ui.py)

## 三灯区灯效

写入区号与读取 selector 使用以下取值。

| 灯区 | API 名称 | 区号 |
| --- | --- | --- |
| 徽标 | `logo` | `0` |
| 滚轮 | `wheel` | `1` |
| 前端灯带 | `front` | `2` |
| 全部灯区广播 | `all` | `3`，用于写入 |

### 灯效读取与 selector 特例

本次实机固件逐区响应 `12 03 zone`。每次查询只从响应中的一组字段解析当前灯区。对区号 `1`、`2` 的查询，应答头也固定为 `12 03 00 00`，因此传输层仅匹配前两个命令字节。

| 响应偏移 | 长度 | 含义 |
| --- | --- | --- |
| `0` | `2` | `12 03` |
| `2` | `1` | 本机固件固定返回 `00` |
| `4` | `1` | 效果码 |
| `5` | `1` | 亮度百分比 |
| `6` | `3` | R、G、B 配置值 |
| `9` | `1` | 保留字段 |
| `10` | `1` | 动画方向 |
| `11` | `1` | 随机颜色开关 |
| `12` | `1` | 动画速度 |

开发期间使用三个不同颜色区分响应，查询 `12 03 00`、`12 03 01`、`12 03 02` 分别得到 `12 03 00 00 00 19 2A 0C 1B`、`12 03 00 00 00 19 2B 0C 1B`、`12 03 00 00 00 19 2C 0C 1B`，后续字段为零。它们对应亮度 25% 的三种独立颜色。单区修改期间也检查了其他区保持原值。

分析到的较旧 P708 HAL getter 使用一次 `12 03 00` 后按三组连续字段解析。该布局与本次实机固件的逐区响应存在差异。当前实现采用实机验证的逐区读取，在扩展到其他固件时应重新检查这一差异。[灯效读取实现](../lighting.py)、[灯效报文测试](../tests/test_lighting.py)

### 灯效写入

```text
51 28 zone 00 mode brightness R G B direction random speed
```

亮度字段为 `0..100` 的百分比，原厂界面的五档亮度分别对应 `0`、`25`、`50`、`75`、`100`。方向 `0` 为顺时针，`1` 为逆时针。随机颜色使用 `0` 或 `1`。彩虹速度 `5`、`7`、`9` 分别为快、中、慢，其他效果的中性速度字段为 `0`。

| 效果码 | 效果 | 当前设置范围 |
| --- | --- | --- |
| `00` | 常亮 | 单区、全部灯区 |
| `01` | 呼吸 | 单区、全部灯区 |
| `02` | 颜色循环 | 单区、全部灯区 |
| `04` | 触发 | 单区、全部灯区 |
| `03` | 彩虹 | 全部灯区 |
| `05` | 彗星 | 全部灯区 |
| `06` | 电量 | 全部灯区 |
| `F0` | 关闭 | 单区、全部灯区 |

有线实测的全区彩虹示例为 `51 28 03 00 03 19 00 00 00 01 00 07`。逐区读回确认了效果、25% 亮度及方向和速度字段。全区彗星的方向 `1`、随机颜色 `1`、速度 `0` 也进行了回读核对。

单区修改会保留未指定字段，并核对三个灯区。全区广播需要显式提供效果、亮度和颜色，避免根据首区推定三个初始状态不同的灯区。高级参数缺省为方向 `0`、随机颜色 `0`，彩虹速度为 `7`，其他效果速度为 `0`。保存后再次读取全部灯区确认。

RGB 配置值表示固定颜色或基色。颜色循环、彩虹、随机彗星和电量效果的实际发光颜色由效果逻辑决定。界面对这些状态显示动态颜色或相应说明，关闭及零亮度显示未点亮，呼吸和触发效果标注配置基色。[灯效业务实现](../lighting.py)、[灯效界面](../light_ui.py)

## 操作边界与验证证据

配置读取、普通设置、板载保存及控制器重新枚举各自具有不同的确认路径。测试和完成声明应保留对应的证据范围。

| 证据来源 | 对实现的作用 | 验证范围 |
| --- | --- | --- |
| G-Helper、libratbag | 提供型号、报文和动作映射参考 | 公开源码中的实现事实 |
| 原厂 MouseSDK、P708 HAL 静态分析 | 核对控制器开关、轴动作编码、物理方向和灯效 setter | 被分析版本的静态构造逻辑 |
| 有线实机报文与 Windows 枚举 | 验证本机固件的读取、设置、恢复及接口变化 | 当前样本和实际执行过的操作 |
| `tests` 中的脚本化传输测试 | 固定偏移、编码、异常与回读校验行为 | 自动化模拟回归 |
| 实际 Tk 控件测试 | 检查当前值显示、草稿和冲突保护 | 界面逻辑和控件交互 |

运行时配置依赖 Windows HID 接口与 hidapi。独立发布程序包含 Python、Tk 和 SQLite 运行环境，配置路径直接发送 HID 报文。原厂组件用于开发期间的静态核对，运行时由本项目实现配置流程。协议说明与报文样本用于复核实现，原厂组件的授权和分发由其供应方管理。[运行说明与验证边界](../README.md)

开发期间的有线验证覆盖 DPI 数值与档位、侧键、板载预设的更改和恢复，游戏控制器接口的出现与消失，以及三灯区和全区动态灯效的配置与回读。四方向映射的实际拨动输入、2.4 GHz 链路、干净 Windows 上的全部实物功能，以及其他固件版本仍需要对应的运行验证。

保存以当前活动预设为上下文，操作中会再次核对预设。单字段设置或四方向连续写入发生中途失败时，鼠标的当前状态可能已经部分改变。收到错误后应重新读取可读配置，再按实际状态决定后续操作。灯效界面核对草稿对应的编辑起点，侧键保存前核对该键的最新回读。上述校验与实机回读可以确认配置结果，实际键盘输入、轴运动和发光表现仍可通过相应交互检查。[按键测试](../tests/test_buttons.py)、[DPI 测试](../tests/test_performance.py)、[灯效测试](../tests/test_lighting.py)、[灯效界面测试](../tests/test_light_ui.py)
